# Contributing to WritingApp

Thank you for helping improve WritingApp.

## Preferred workflow

1. Read `ACCESSIBILITY.md`.
2. Open an Issue describing the proposed approach.
3. Include links to relevant primary documentation when possible.
4. For code, use a fork or branch and submit a pull request.
5. Describe how the change was tested with a keyboard and screen reader.

Pull requests are proposals. They cannot modify the main project unless the
project owner explicitly reviews and merges them.

## Accessibility changes

For changes involving the editor, include:

- Windows version;
- JAWS or other screen-reader version;
- exact steps and keys used;
- exact speech output;
- whether any mode-change sound occurred;
- whether ordinary typing, selection and editing still worked.

Please avoid solutions that merely change the editor's accessible name on
caret movement. That approach has already caused duplicated and triplicated
speech.

## Scope

The public repository should contain source code and technical documentation
only. Do not commit:

- personal documents;
- test documents containing personal information;
- recovery files;
- compiled executables or DLLs;
- credentials, tokens or local machine paths.
